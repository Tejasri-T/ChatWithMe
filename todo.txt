### 1. Decouple Architecture & Introduce an API Layer
**Current State:** [frontend.py](file:///D:/ai_projects/chatbot/frontend.py) and [backend.py](file:///D:/ai_projects/chatbot/backend.py) run in the same Python process. Every Streamlit interaction reruns the script, blocks the GIL, and cannot scale horizontally.

* **API Gateway / Backend Service:** Wrap your LangGraph chatbot in **FastAPI** or **Litestar**.
  * Use **Server-Sent Events (SSE)** or **WebSockets** for token-by-token streaming instead of synchronous yields in UI code.
  * Separate long-running background tasks (PDF parsing, OCR, vector embedding) using a worker queue (**Celery**, **ARQ**, or **Redis Queue**).
* **Decoupled Frontend:**
  * Build a dedicated web/mobile client in **Next.js**, **React**, or Flutter. Streamlit can be retained as an internal testing or admin dashboard.

### 2. Scalable Data Persistence & Storage
**Current State:**
* FAISS vector stores are held in-memory in a Python dictionary (`_THREAD_RETRIEVERS = {}`). If the server restarts or scales to multiple instances, all indexed vectors are lost.
* Chat history and thread names use a local file (`chatbot.db`) via `SqliteSaver` with `check_same_thread=False`, which causes locking errors under concurrent traffic.

* **Dedicated Vector Database:**
  * Replace the per-process FAISS dict with a production vector DB: **PostgreSQL with `pgvector`** (cost-effective, unified database), **Qdrant**, or **Milvus**.
  * Index documents with tenant and thread metadata namespaces (`tenant_id`, `user_id`, `thread_id`) so queries are scoped securely.
* **Production Checkpointer & State:**
  * Switch LangGraph from `SqliteSaver` to **`PostgresSaver`** (native to LangGraph) or Redis for active conversation states.
* **Blob / Object Storage:**
  * Store uploaded PDFs in **AWS S3**, **Google Cloud Storage (GCS)**, or **Cloudflare R2** rather than temporary local disk paths (`tempfile.NamedTemporaryFile`). Store file URIs and metadata in PostgreSQL.

### 3. Production-Grade RAG & Agent Capabilities
**Current State:** Simple character-based splitting (`RecursiveCharacterTextSplitter`) with basic vector top-K similarity search and hardcoded Gemini models.

* **Advanced Document Parsing:**
  * Real-world PDFs contain complex layouts, tables, and images. Upgrade from basic `PyPDFLoader` to parsing engines like **Docling**, **Unstructured**, or **LlamaParse**.
* **Hybrid Search & Re-ranking:**
  * Combine semantic dense retrieval (embeddings) with keyword search (**BM25 / Full-Text Search**) using Reciprocal Rank Fusion (RRF).
  * Add a **Re-ranker** (e.g., Cohere Re-rank, BGE-Reranker, or FlashRank) to re-order the top 20 candidates down to the top 3–5 most relevant chunks before passing to the LLM.
* **Model Resilience & Fallbacks:**
  * Support fallback LLM providers (e.g., fall back to Gemini Pro or Claude/OpenAI if Flash Lite experiences rate limits or downtime).
  * Enforce maximum execution timeouts and circuit breakers for external tools (DuckDuckGo search, RAG retrieval).

---

### 4. Security, Authentication & Multi-Tenancy
**Current State:** Anyone can access or overwrite threads without authentication. Files are uploaded without verification or sanitization.

* **User Authentication & Authorization (RBAC):**
  * Integrate OAuth2/OIDC or JWT authentication (e.g., Supabase Auth, Auth0, Clerk, or FastAPI OAuth).
  * Ensure strict data isolation: Users should only ever query and retrieve their own conversations and indexed documents.
* **Input/Output Guardrails:**
  * Implement guardrails (**NeMo Guardrails**, **Llama Guard**, or **Guardrails AI**) to prevent prompt injections, jailbreaks, and sensitive data leakage.
  * Sanitize tool inputs and outputs.
* **File Upload Protections:**
  * Validate file magic bytes (not just `.pdf` file extensions).
  * Enforce file size limits (e.g., 25MB) and scan uploads for malicious payloads / decompression bombs.

---

### 5. Observability, Evaluation & Monitoring (LLMOps)
**Current State:** Debugging is limited to standard `print` statements without cost or latency tracking.

* **Agent Tracing & Debugging:**
  * Integrate an LLM observability tool such as **Langfuse**, **Arize Phoenix**, or **LangSmith**. Trace every node execution, tool call, token consumption, and latency spike.
* **Application Metrics & Logging:**
  * Structured JSON logging (e.g., using `structlog`).
  * System metrics via **Prometheus** and dashboards in **Grafana** (tracking active requests, P95/P99 latency, LLM token costs, error rates).
* **Automated Evaluation (Evals):**
  * Build an evaluation pipeline using **Ragas** or **DeepEval** to measure RAG faithfulness, answer relevancy, and context recall in your CI/CD pipeline before pushing new prompts or chunking strategies.

### 6. DevOps, Infrastructure & CI/CD
**Current State:** No Git tracking, no dependency lockfile, and no container configuration.

* **Environment & Package Management:**
  * Initialize version control (`git init`).
  * Replace loose dependencies with a modern package manager and lockfile: **`uv`** (`pyproject.toml`) or **Poetry**.
* **Containerization:**
  * Create optimized, multi-stage **Dockerfiles** for the API server, background workers, and frontend.
  * Provide a `docker-compose.yml` defining the API, PostgreSQL + pgvector, Redis, and Langfuse for local development.
* **CI/CD Automation:**
  * GitHub Actions / GitLab CI for:
    * Linting & formatting (`ruff`).
    * Static type checking (`mypy`).
    * Automated test suites (`pytest` for agent state transitions and tool execution).
* **Deployment & Cloud Infrastructure:**
  * Deploy on managed container services (AWS ECS / EKS, GCP Cloud Run / GKE, or Kubernetes).
  * Manage secrets using AWS Secrets Manager, GCP Secret Manager, or HashiCorp Vault instead of `.env` files.
